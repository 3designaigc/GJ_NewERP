# 出貨文件與歸檔流程

建立日期：2026-06-15

## 1. 系統目標

- ERP 內有文件追蹤資料、缺件狀態、核對結果與歷史紀錄。
- Google Drive / 本機資料夾有固定歸檔結構，日後可依 PO 或訂單號查回完整文件。


## 2. 標準流程

```text
國際採購下單
        ↓
建立訂單文件資料夾
        ↓
供應商 / TDS 回 PI
        ↓
PI 核對價格、品名、規格、數量、付款條件
        ↓
PI 通過後進入出貨文件追蹤
        ↓
出貨前追 CI / PL / COO / HC / COA
        ↓
出貨後追 B/L
        ↓
文件核對不符則退回修正
        ↓
文件通過後連動船班、報關、付款與現金流
        ↓
收款流程結束後移入已完成歸檔
```

## 3. Google Drive 資料夾規則

每張已下單的採購單都必須有獨立資料夾。

資料夾命名：

```text
{PO或訂單號}-{供應商}-{客戶}
```

標準子資料夾：

```text
00_採購單_PO與核准紀錄
01_PI_ProformaInvoice
02_CI_CommercialInvoice
03_PL_PackingList
04_COO_產地證明
05_HC_COA_衛生證明與分析報告
06_BL_提單
07_船班與報關
08_修正版與往來紀錄
99_已完成歸檔
```

收款流程結束後，整個訂單資料夾移入：

```text
..已完成（收款流程結束）
```

## 4. 必備文件

| 文件 | 階段 | 核對重點 |
|---|---|---|
| PO | 下單 | PO號、供應商、客戶、交易模式、付款條件、商品明細、數量、單價、總額 |
| PI | PI核對 | 品名、規格、數量、箱數、單價、總額、幣別、Incoterms、付款條件 |
| CI | 出貨前 | 品名、數量、單價、總額、產地、收貨人、Invoice No. |
| PL | 出貨前 | 箱數、箱入數、Gross weight、Net weight、棧板數、尺寸、批號 |
| COO | 出貨前 | 產地、供應商、收貨人、品名、重量、發證單位 |
| HC | 出貨前 | 品名、產地、製造商、批號、效期、衛生證明號 |
| COA | 出貨前 | 批號、檢驗項目、結果、日期、製造商 |
| BL | 出貨後 | B/L No.、船名、航次、ETD、ETA、收貨人、Notify party、櫃號 |

## 5. ERP JSON 結構

第一階段新增：

```text
json/document_archive_rules.json
```

用途：

- 定義 Drive 根資料夾
- 定義訂單資料夾命名規則
- 定義標準子資料夾
- 定義必備文件與核對欄位
- 定義文件狀態流程
- 暫存雲端待掃描資料夾清單

後續正式資料庫建議拆成：

| 資料表 | 說明 |
|---|---|
| `document_archives` | 每張 PO 的文件歸檔主檔 |
| `document_files` | 每份文件版本、連結、檔名、狀態 |
| `document_check_items` | 文件核對欄位與核對結果 |
| `document_followups` | 催件、修正、窗口與日期 |
| `drive_folder_links` | Google Drive Folder ID 與路徑 |
| `document_audit_logs` | 文件版本與操作紀錄 |

## 6. ERP 頁面

目前原型已新增 `文件歸檔` 頁面。

頁面包含：

- 訂單文件歸檔規則
- 標準資料夾結構
- 文件狀態流程
- 必備文件與核對欄位
- 雲端資料夾待處理清單

權限：

- 業務：不可看
- 業務主管：可看
- 本人：可看

## 7. 雲端文件處理方式

取得 Google Drive 資料夾連結後，系統要做：

1. 讀取 `供應鏈 / 訂單文件` 下所有訂單資料夾。
2. 依資料夾名稱解析 PO / 訂單號、供應商、客戶。
3. 掃描每個資料夾內是否已有 PI、CI、PL、COO、HC、COA、B/L。
4. 判斷缺件、文件不符、是否已完成。
5. 把掃描結果寫回 ERP 文件歸檔資料。
6. 已完成收款流程的資料夾移入 `..已完成（收款流程結束）`。

注意：移動雲端資料夾屬於會改變外部資料的操作，正式執行前需要本人確認。
