# 轉單文件製作規則

建立日期：2026-06-15

依據 Google Drive `供應鏈 / 訂單文件 / SM260515-26FA0008` 中檔名含 `小T` 的轉單文件，以及同資料夾內客戶 PO、GJ 給工廠 PO、工廠 PI 比對建立。

## 1. 0515 樣本交易模式

`SM260515-26FA0008` 是 C 類買進轉手模式，交易鏈如下：

```text
Simple Mart Plus 美廉
        ↓ 客戶 PO
NEXO Resources
        ↓ NEXO 給高玉 PO
Golden Jade Terre 高玉
        ↓ 高玉給工廠 PO
MAS CHOICES 泰國供應商
```

這筆不是單純把同一份文件換抬頭。它有兩層售價與一層採購成本：

| 層級 | 文件方向 | 金額 |
|---|---|---:|
| 客戶層 | NEXO → Simple Mart | USD 40,752.00 |
| 高玉/NEXO層 | Golden Jade → NEXO | USD 40,302.00 |
| NEXO留利 | 客戶層 - 高玉/NEXO層 | USD 450.00 |
| 供應商成本 | Golden Jade → Mas Choices | USD 32,805.40 |

0515 客戶金額大於 USD 10,000，所以 C 類規則套用 NEXO 留利 USD 450。此折讓只出現在 GJ-NEXO 層，不可以出現在 NEXO-SM 客戶層。

## 2. 0515 小T 文件清單

## 3. 金額規則

1. 先讀客戶 PO 與最終確認數量，建立客戶層總額。
2. 判斷交易模式是否為 C 類買進轉手。
3. C 類若客戶最終金額大於 USD 10,000，NEXO 留利 USD 450。
4. C 類若客戶最終金額小於或等於 USD 10,000，NEXO 留利 USD 150。
5. GJ-NEXO 層金額 = 客戶層金額 - NEXO 留利。
6. NEXO-SM 層金額 = 客戶層金額，不扣 NEXO 留利。
7. GJ-Supplier 層金額 = 供應商成本，不使用客戶轉售價。
8. G7 是例外，不套 NEXO 留利，改走 TDS / Feast 模式。

0515 實際計算：

```text
NEW_TGO: 700 CTNS x USD 30.24 = USD 21,168.00
NEW_TGW: 680 CTNS x USD 28.80 = USD 19,584.00
客戶層總額 = USD 40,752.00
NEXO留利 = USD 450.00
GJ-NEXO淨額 = USD 40,302.00

供應商成本:
NEW_TGO: 700 CTNS x USD 24.25 = USD 16,975.00
NEW_TGW: 680 CTNS x USD 23.28 = USD 15,830.40
供應商成本合計 = USD 32,805.40
```

## 5. 製作順序

```text
讀取客戶 PO
        ↓
確認最終出貨數量與品項
        ↓
建立 NEXO-SM 客戶層 PI / CI / PL
        ↓
套用 C 類 NEXO 留利
        ↓
建立 NEXO-GJ PO 與 GJ-NEXO PI / CI / PL
        ↓
讀取供應商報價或 PI
        ↓
建立 GJ 給供應商 PO
        ↓
核對三層金額、品項、箱數、條碼、付款條件
        ↓
歸檔至該訂單資料夾
```

## 6. 系統檢查規則

- 同一訂單所有文件的品名、條碼、規格、產地、箱入數必須一致。
- PI、CI、PL 的最終箱數必須一致；0515 為 1,380 CTNS。
- NEXO-SM 金額減 GJ-NEXO 金額必須等於 NEXO 留利。
- GJ-NEXO 金額減供應商成本是高玉毛利基礎。
- GJ-Supplier 文件不可露出 NEXO 客戶售價。
- NEXO-SM 文件不可露出高玉供應商成本與 NEXO 留利。
- PL 不列金額，但 Buyer、Consignee、Shipping Marks 必須依文件層級切換。
- 每個供應商獨立建單；同一客戶同一供應商可以一張訂單多產品。
- 下過的訂單必須歸檔，保留日後查詢。
